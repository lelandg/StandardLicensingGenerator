# Plan: Issues #11, #14, #16 — templates, MVVM, portable release

**Branch:** `feat/templates-mvvm-portable` (from `origin/main` @ c7535de)
**Date:** 2026-08-26
**Order:** #11 → #14 → #16, per Leland's direction (simplest first).

Each issue has an investigation comment with a proposed design. This plan
adapts those proposals to the current code (post-MahApps merge, PR #15).

## Step 1 — Issue #11: License templates

Goal: save and recall named sets of license parameters.

- **New `Models/LicenseTemplate.cs`** — DTO with explicit fields:
  `Name`, `ProductName`, `Version`, `LicenseType`, `ValidityDays` (relative,
  so a template does not carry a stale absolute date), `CustomerName`,
  `CustomerEmail`, `AttributesJson`, `KeyFilePath`. **No password field.**
  A signed license must not leak its signing secret into a plaintext store.
- **New `Models/LicenseTemplateStore.cs`** — `Load()` / `Save(list)` against
  `%APPDATA%\StandardLicensingGenerator\Templates.json` (`System.Text.Json`,
  indented, ignore corrupt files — same behavior as `WindowSettingsManager`).
  Name match is case-insensitive; save over an existing name asks Yes/No via
  `Views.CustomMessageBox`.
- **UI (`MainWindow.xaml`)** — new "Template:" row above Product Name:
  ComboBox (select applies the template) + "Save Template" + "Delete" buttons.
- **Apply order:** set `LicenseTypeBox` first (its `SelectionChanged`
  auto-fills Trial defaults), then overwrite the remaining fields from the
  template.
- **Persistence guard:** `WindowSettingsManager` persists every named
  control. The template ComboBox must not be persisted, or its restored
  `SelectedIndex` would re-apply a template on startup and clobber the
  restored field values. Add a generic opt-out to `WindowSettingsManager`:
  skip any control whose `Tag` is `"NoPersist"`.
- **Security fix (adjacent, same mechanism):** `PasswordTextBox` in both
  windows is a plain `TextBox` mirror of the `PasswordBox`, so the key
  password is currently saved in plaintext to `MainWindow.json` /
  `KeyPairGeneratorWindow.json`. Mark both mirrors `Tag="NoPersist"`.
  This repo's rules forbid persisting secrets; the fix is one attribute per
  control once the opt-out exists.
- Docs: README + HelpWindow get a Templates section (they duplicate content
  by convention).

## Step 2 — Issue #14: MVVM migration

Goal: presentation logic in ViewModels, bindings + commands, testable.

- **Package:** `CommunityToolkit.Mvvm` (stated reason: standard source-getter
  MVVM toolkit; avoids hand-rolling `INotifyPropertyChanged`/`RelayCommand`).
- **New `ViewModels/`**: `MainWindowViewModel`, `KeyPairGeneratorViewModel`.
  Move into them: license build + JSON attribute parsing invocation, trial
  store/restore logic, template load/apply/save/delete, key-pair generation.
- **New `Services/`**: `IDialogService` (wraps `CustomMessageBox` + file
  dialogs) so ViewModels never touch UI types; `MainWindow`/`KeyPair` views
  supply the implementation.
- **Views**: bind `TextBox`/`ComboBox`/`DatePicker` to VM properties,
  buttons to `RelayCommand`s. `PasswordBox` cannot two-way bind securely;
  keep a thin code-behind sync into the VM (`string Password`), and dedupe
  the show/hide-password logic shared by both windows into one helper.
- **Constraints:**
  - Behavior must not change (issue acceptance criterion). License output
    bytes, attribute round-trip, and dialogs stay identical.
  - `WindowSettingsManager` restores controls by `x:Name` after `Loaded`.
    Keep `x:Name` on bound controls with
    `UpdateSourceTrigger=PropertyChanged` bindings so a restored control
    value flows into the VM. Verify the restore → VM path explicitly.
- **New test project** `StandardLicensingGenerator.Tests` (xunit,
  `net10.0-windows`), added to the `.slnx`. Tests target VM logic:
  template apply/save, trial defaults store/restore, attribute JSON
  round-trip (keys case-sensitive, values verbatim), validation failures.

## Step 3 — Issue #16: Portable release

Goal: self-contained win-x64 build attached to each GitHub release.

- **New `.github/workflows/release.yml`** — trigger `push: tags: ['v*']`
  (never `pull_request_target`), `windows-latest`, .NET 10, `dotnet publish
  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
  -p:IncludeNativeLibrariesForSelfExtract=true`, zip, attach via
  `softprops/action-gh-release@v2`.
- **README** — add a Download section; fix stale `net9.0` /
  "targets .NET 9.0" references; document the portable build command and
  the `%APPDATA%` settings footprint (portable ≠ zero-footprint).
- **HelpWindow** — mirror user-facing changes.

## Finish

- WSL verification build per step; full build + `rm -rf obj bin` at the end

- Version bump + changelog via the version tool in one commit (minor bump —
  three features).
- Local review, then stop. Push/PR only when Leland asks.

## Known issues deliberately NOT fixed here

  (`WithProductFeatures` is commented out). Wiring them in changes signed
  output — a downstream-visible change that needs its own decision/issue.
- Key Size ComboBox does not affect `KeyGenerator.Create()`.
- `MaximumUtilization` is hardcoded to 5.
